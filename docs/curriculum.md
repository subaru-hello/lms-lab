# 実装ロードマップ — 壊れるシステム・壊れないシステム / LMS編

**貫く問い: 「買った人にだけ、期限つきで、動画を見せる」をどう実装しきるか。**

9セクション40段。記事・Shortsへの割り付けは docs/distribution.md。
技術構成: Next.js(App Router) + TypeScript(strict) + Postgres(Drizzle) + Cloudflare R2 + Stripe。S8のみ Cloudflare Stream。
業務ルールの正: `docs/domain-requirements.md`。収録規約: `docs/recording.md`。

方針:
- git タグ運用。段Nに `lNN-start` / `lNN-broken`(該当回のみ) / `lNN-complete` を打つ
- 逐語台本は作らない。ラフ台本(話す流れ・キーフレーズ・コード手順)は `docs/scripts/` に1セクション1ファイル
- 山場は「壊れた状態を先に作って実行して見せる → 直す」の型で撮る(詳細は recording.md)

## S1 導入(25分) ※パイロット収録セクション

- **1.1 完成物デモ(6分)**: 未購入で動画URLを直叩き→403 / 購入後に再生 / 期限を切らして再度403。この3画面をColdOpenで見せる。「これ、ちゃんと作れますか?」
- **1.2 このシリーズが答える一つの問いと、作らないもの**: 貫く問いの提示。CRUD止まりのLMSとの違い。作らないもの(SNSログイン/掲示板/SCORM等)を先に宣言してスコープを閉じる
- **1.3 環境構築とタグの歩き方(6分)**: Node22 + Next.js + Postgres(docker) の起動。`lNN-start`/`lNN-complete` の使い方。エディタは何でもよい(講師はnvim)
- **1.4 業務ルールを読む(7分)**: domain-requirements.md の10項目を読む。特に「支払いの事実」と「視聴する権利」を分ける話。「この権利、どこに持たせる?」で次章へ

## S2 ドメインとデータモデル(40分)

- **2.1 LMSの5つの名詞(8分)**: Course/Lesson/Purchase/Enrollment/Progress と関係を図で描く。ER図をここで1枚に固定する
- **2.2 権利は「誰が・何を・いつまで」(10分)**: Purchase と Enrollment を分ける理由。返金でアクセス権だけ剥がせる形。expiresAt を持たせる設計判断
- **2.3 Drizzleでスキーマとマイグレーション(12分)**: テーブル定義、外部キー、一意制約(userId+courseIdの重複Enrollment禁止)。マイグレーション実行
- **2.4 なぜLessonに動画URLを持たせないのか(10分)**: URLをカラムに置くと、それを返した瞬間に権利チェックが効かなくなる。持たせるのはストレージキーだけ。S5への伏線

## S3 認証と権限モデル(45分)

- **3.1 認証と認可を分ける(7分)**: 「誰か」と「何をしてよいか」は別問題。混ぜると権限の穴が生まれる
- **3.2 セッションを実装する(10分)**: メール+パスワードのサインアップ/ログイン、セッションCookie、ロール保持
- **3.3 権限表をコードに落とす(12分)**: 3ロール×操作の表を作り、`can(user, action, resource)` の1関数に集約する。表を先に作ってから実装する
- **3.4 どこで権限を見るか(11分)**: Server Component の描画時と Route Handler の両方で見る(二重防御)。UIを隠すのは権限制御ではない、を実演で示す
- **3.5 演習: 講師は自分のコースだけ編集できる(5分)**: startコードと期待テストを渡す

## S4 動画を置いて再生する(40分)

- **4.1 公開バケットに置くと何が起きるか(8分)**: まず公開R2に置いて再生させ、URLをコピーしてシークレットウィンドウで開く。誰でも見られる状態を目で見せる
- **4.2 R2への署名付き直接アップロード(12分)**: サーバーを経由せずブラウザから直接PUTする。なぜサーバー経由にしないか(帯域と実行時間)
- **4.3 HLSとは何か(12分)**: 1本のmp4を数秒ごとに分割し、目次(m3u8)で並べる。ffmpegで実際に作って中身をcatで見せる
- **4.4 hls.jsで再生する(8分)**: video要素にアタッチ。ネットワークタブでセグメントが順に取られていくのを見せる

## S5 買った人にだけ見せる(55分) ※講座の山場

- **5.1 署名URLの中身を手で作る(12分)**: 期限とパスをHMACで署名し、クエリに載せる。検証側を書く。ライブラリを使う前に手で作る
- **5.2 m3u8の中のセグメントにも署名が要る(12分)**: 目次だけ署名して満足すると、セグメントが素通しになる。実際に破って見せてから直す
- **5.3 Enrollmentを確認してから署名を発行する(12分)**: 署名発行のRoute Handler。ここが権利チェックの唯一の関門になる設計
- **5.4 署名の寿命をどう決めるか(9分)**: 短いと長い動画の途中で切れる、長いと共有される。実際に10秒にして再生を切らせてから、妥当な値を決める
- **5.5 それでも漏れる、の線引き(5分)**: 画面録画とアカウント共有は技術で止まらない。透かし・同時視聴数という現実的な打ち手と、やらない判断
- **5.6 演習: 期限切れEnrollmentで403(5分)**

## S6 決済とアクセス権の整合(50分)

- **6.1 Stripe Checkoutでコースを売る(10分)**: 価格の作成、Checkout Session、テストカードで通す
- **6.2 リダイレクトで決済完了を判定してはいけない(10分)**: 成功URLを直接叩いて、払わずにEnrollmentを得る。実際に破って見せる
- **6.3 Webhookの署名検証と冪等性(14分)**: `stripe listen` でローカルに転送。同じイベントを二度投げてEnrollmentが二重に増えるのを見せてから、event.idで冪等にする
- **6.4 返金でアクセス権を失効させる(10分)**: charge.refunded を受けてEnrollmentをrevoke。Purchaseは消さない(2.2の設計が効く場面)
- **6.5 失敗したWebhookをどう拾うか(6分)**: 再送の仕組み、処理済みイベントの記録、詰まったときに人が見る場所

## S7 進捗を記録する(35分)

- **7.1 「見た」をどう定義するか(8分)**: 再生開始か、最後まで到達か、90%か。定義を決めないと数字が意味を持たない
- **7.2 進捗APIと送信頻度(12分)**: 毎秒送るとどうなるかを計算で見せ、15秒間引き+離脱時送信にする
- **7.3 レッスン完了とコース修了率(8分)**: 完了判定と集計クエリ
- **7.4 講師ダッシュボード(7分)**: どのレッスンで脱落しているかを出す

## S8 マネージドに逃がす判断(30分)

- **8.1 Cloudflare Streamで同じことをする(12分)**: signed tokenでS5と等価の制御を実現する。自前実装との対応を1対1で示す
- **8.2 自前HLSとマネージドの比較(10分)**: 費用・運用・止まったときの打ち手。数字を並べる
- **8.3 どこで乗り換えるべきか(8分)**: 判断基準。S5を自分で書いたからこそ、何を買っているのかが分かる

## S9 仕上げと公開(35分)

- **9.1 買う→見る→期限切れをE2Eで通す(12分)**: Playwrightで一本の筋を通す。この講座の主張がテストとして残る
- **9.2 デプロイと秘密情報(10分)**: 本番環境、環境変数、鍵のローテーション
- **9.3 ローンチ前チェックリスト(8分)**: 権限の穴・Webhook再送・最低限の監査ログ
- **9.4 ここから先の地図(5分)**: SSO・多言語・SCORM・ライブ配信。何が難しいかだけ示す
