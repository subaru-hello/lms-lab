# 収録規約(1枚)

毎回この設定で録る。途中で変えると講座全体の統一感が壊れるので、S1のパイロットで確定させてから本収録に入る。

## OBS

- 解像度 1920x1080 / 30fps / 画面キャプチャ+マイクのみ(顔なし・ワイプなし)
  - ※ 2026-09-02の試し録りは60fpsだった。パイロットで30/60を決めて、以後固定する
- 音声フィルタ: ノイズ抑制(RNNoise)→コンプレッサー→リミッター(-6dB)
- 録画形式: mkvで録ってmp4にリマックス(収録中クラッシュでもファイルが残る)
- **保存先を `~/Movies/UdemyLMS/` に変更する**。既定の `~/Movies/Lessons/` は英語レッスンの録画置き場なので混ざる
- 収録前チェック: 10秒試し録り→再生して音量・ノイズ・カーソル視認性を確認してから本番

## 画面(エディタ / ターミナル / ブラウザ)

- フォントサイズ 20pt以上(スマホ視聴で縮小されても読める下限)。パイロットで実機確認して確定
- カラースキームは1つに固定(全編統一)。行番号ON・不可視文字OFF
- ペイン構成を固定: 左=エディタ、右上=`pnpm dev` のログ、右下=テスト/CLI。毎レクチャー同じ配置
- ブラウザは収録専用プロファイル(ブックマークバー非表示・拡張なし・履歴に個人情報が出ない)
- 通知(Slack/メール/OSバナー)を全OFF。おやすみモードON
- Stripeダッシュボード・R2コンソールを映すときは、テスト環境かつ他プロジェクトが見えない状態にする

## マイク

- 口元から15cm前後・正面よりやや斜め(破裂音対策)
- 録る時間帯を固定(環境音の一貫性)。エアコン・換気扇は可能ならOFF
- 声量は「対面で1人に説明する」程度。張り上げない

## 実況スタイル

- ラフ台本(`docs/scripts/`)の流れに沿って喋る。**読み上げない**
- 言い間違えたら止めずに言い直して続ける(編集で切る前提。無音3秒を編集点の目印にする)
- コードを打ちながら「今から何をするか」を先に言う(打ってから説明しない)
- 1レクチャー=1収録ファイル。10分超えたら分割を検討

## 実装過程の見せ方(この講座の核)

完成リポジトリを先に作り切ってから収録するが、これは「実装過程を見せない」という意味ではない。
収録を発見の場ではなく再現の場にして、見せる価値のある区間を確実に撮るための準備。
レクチャーごとに、その回の差分を3段階に仕分けてから収録に入る。

1. **白紙から手で書く** — その回の判断が宿る1〜2ファイル。差分の2〜3割。打つ前に何をするかを言う
2. **貼って説明する** — 判断は説明済みで量が要るもの(スキーマの残り、UIマークアップ、テストの並び)。貼った直後に「なぜこの形か」を1文。読み上げない
3. **見せずに済ませる** — 依存追加、生成物、ダッシュボードの画面ぽちぽち。「これは済ませてあります」と言って complete タグを案内する

### 壊してから直す型(山場のレクチャー)

S4.1 / S5.2 / S5.4 / S6.2 / S6.3 は、**壊れた状態を先に作って実行して見せてから直す**。

- S4.1: 公開バケットのURLをシークレットウィンドウで開き、誰でも見られるのを見せる
- S5.2: 目次(m3u8)だけ署名して、セグメントが素通しなのを見せる
- S5.4: 署名の寿命を10秒にして、再生が途中で切れるのを見せる
- S6.2: 成功リダイレクトURLを直接叩いて、払わずにEnrollmentを得る
- S6.3: 同じWebhookイベントを二度投げて、Enrollmentが二重に増えるのを見せる

これがこの講座で最も価値のある区間。完成コードが先にあるからこそ確実に撮れる
(ライブコーディングだと失敗が撮り直しに直結して、この型は撮れない)。

「完成コードを先に見せてから解説」を使うのは **S1.1 の完成物デモだけ**。
それ以外のレクチャーは、必ず動く状態から動く状態への差分として撮る。

## 配布コード(git タグ運用)

- レクチャーNに対して `lNN-start` と `lNN-complete` のタグを打つ
- start は「前レクチャーの完成状態 + 今回の空ファイル/TODO」、complete は動く完成状態
- 各 complete タグで `pnpm typecheck` と `pnpm test` が通ることを確認してからタグを打つ
- 受講者配布は `scripts/export-lecture.sh lNN` でzipを吐く

## 公開運用

- 記事(Zenn)が一次資料。Shortはその抜粋であり、記事を書く前にShortを作らない
- Shortのタイトルは【壊れるシステム】をカテゴリタグとして先頭に固定し、シリーズ内で揃える
- 実装リポジトリは公開(github.com/subaru-hello)。記事から `lNN-broken` / `lNN-complete` タグに直接リンクする
- 記事・Short・Xの割り付けは `docs/distribution.md`
