# ドメイン要件 — 講座題材のLMS

この講座で作るLMSの業務ルール。実装もラフ台本も、このファイルを唯一の正とする。
ここに書いていないものは作らない。迷ったらここに戻る。

## 登場人物（3ロール）

- **受講者(student)**: コースを購入し、動画を視聴し、進捗が記録される
- **講師(instructor)**: 自分のコースを作成・編集・公開し、受講者の進捗を見る
- **管理者(admin)**: 全コースを見られる。返金対応でアクセス権を失効させる

## 5つの名詞

| 名詞 | 意味 | 同一性 |
|---|---|---|
| Course | 販売単位。価格とレッスンの並びを持つ | ID |
| Lesson | 動画1本。Courseに属し、順序を持つ | ID |
| Purchase | 支払いの事実。Stripeのイベントと1対1 | ID(Stripe event由来) |
| Enrollment | **視聴する権利**。誰が・どのCourseを・いつまで | ID |
| Progress | 誰が・どのLessonを・どこまで見たか | (userId, lessonId) |

Purchase と Enrollment を分けるのがこの講座の設計上の要。
支払いの事実は消えないが、視聴する権利は返金で消える。同じテーブルに入れると剥がせない。

## 業務ルール

1. 講師は自分のコースだけ作成・編集・公開できる。他人のコースは読むことすらできない
2. コースは下書き(draft)と公開(published)を持ち、下書きは講師本人と管理者にしか見えない
3. 受講者は購入して初めて Enrollment を得る。無料公開レッスン(preview)はCourseごとに1本まで指定でき、Enrollmentなしで見られる
4. Enrollment には有効期限(expiresAt)がある。買い切りはnull(無期限)、期間つきは日時。期限切れは視聴不可
5. 動画は非公開ストレージに置く。視聴のたびに、有効な Enrollment を持つ人にだけ**短命の署名URL**を発行する
6. 決済完了の判定は成功リダイレクトではなく **Webhook** で行う
7. 同じ Webhook イベントが二度届いても Enrollment を二重に作らない(event.id で冪等にする)
8. 返金・チャージバックのイベントが届いたら、対応する Enrollment を失効させる
9. 進捗は再生位置を間引いて(15秒ごと程度)記録する。レッスンの90%到達で完了とみなす
10. コース修了率 = 完了レッスン数 / 公開レッスン数

## 作らないもの（講座内で明言する）

SNSログイン / 掲示板・Q&A / モバイルアプリ / SCORM・xAPI / 多言語 / クーポン / アフィリエイト。
「決定版」を名乗る根拠は網羅ではなく、ルール4〜8を最後まで詰めることに置く。
